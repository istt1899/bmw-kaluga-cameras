# Waze Стрелка

Версия приложения 0.2.1 для BMW MGU / iDrive 7. Приложение основано на полном открытом Waze on Cluster: исходник `robertn_waze_cluster` 0.6.0 из `robertnisipeanu/idrive-apps`, commit `daaa3f704132304bdd6c4552a33d7c550244672e`. Сохраняет главное меню, карту на приборах/HUD, размер и положение HUD, настройки CarPlay и Android Auto, скрытие подсказок BMW, журналы, захват и экспорт журналов с QR-кодом. Добавлены раздел камер и регулировка прозрачности HUD.

Это приложение управляет штатным зеркалированием карты телефона через общие `waze-on-cluster` и `cluster-render`. При использовании Яндекс Карт регулируется тот же видеослой; возможности карты и ограничения потока определяются телефоном и поддержкой этих общих сервисов. Наличие меню не подтверждает работу всех режимов конкретного автомобиля.

## Обновление

Источник в Store: `istt1899/bmw-kaluga-cameras`, канал **Releases**. Прямой HTTPS-каталог: `https://raw.githubusercontent.com/istt1899/bmw-kaluga-cameras/main/catalog.json`; короткий адрес: `https://tinyurl.com/24appypy`.

Обновить приложение до **0.2.1**; сервис камер остаётся **0.2.0** на стоящей машине. Название прежнего приложения «Камеры • Калуга» станет **Waze Стрелка**. Его идентификатор `marku_kaluga_cameras` и UUID сохранены для обновления на месте. Сервис камер сохраняет идентификатор `marku-kaluga-cameras`. Общие зависимости: `waze-on-cluster` 0.9.0, `cluster-render` 0.4.0, `mgu-deploy` 0.7.11 или новее. Публичный каталог включает проверенные ссылки на официальные общие сервисы.

После установки выполнить перезапуск головного устройства, если Store показывает такую необходимость. Открыть **Приложения → Waze Стрелка**. Сервис карт управляется теми же настройками, что в исходном Waze on Cluster; камера не блокирует эти настройки при своей ошибке.

## Прозрачность HUD

В разделе **HUD** ползунок **Прозрачность HUD**: 0 % — исходная яркость карты, 90 % — минимальная плотность карты. Настройка сохраняется сервисом и действует на зеркалируемую карту, в том числе Яндекс Карты. Карта на приборной панели не меняется. При недоступном сервисе ползунок выключен, неподтверждённое значение не выдаётся за применённое.

Реализация: чёрный альфа-слой над видеослоем общего renderer и под предупреждениями камер. Уровень 40 % прозрачности оставляет 60 % света видеокарты. Отдельный штатный HUD не изменяется; другие пользовательские слои той же сцены ниже затемнения также приглушаются. Слой снимается при выключении карты и при устаревании её файла состояния. Сервис читает `/run/waze-on-cluster/status.json`; единственное управляющее соединение Waze остаётся доступным интерфейсу.

## Камеры и GPS

Раздел **Камеры** показывает базу, положение, состояние сервиса, выходы на приборы и HUD и диагностику. Комплектный снимок OSM Калужской области содержит **150 точек**, в том числе 36 в Калуге, 52 с числовым лимитом; только 19 зон имеют нужные сведения о дороге и направлении для условного предупреждения. Это ограниченный снимок, а не полная база действующих комплексов. Аудиопредупреждения и автоматическое обновление базы не реализованы.

Камеры используют только свежие GPSD/NMEA-координаты с проверяемыми временем, точностью, курсом и соответствием дороге. Сама видеокарта Waze/Яндекса не предоставляет координаты. **Работающий источник координат данной MGU ещё не подтверждён.** Без него предупреждения не выдаются; координаты и расстояния не подставляются. Найденный в другом открытом приложении интерфейс `de.bmw.infotainment.GPSData` / `GPSPositionExtendedCAN` требует чтения и проверки типов на собственной машине до использования; масштабы полей не угаданы и не внедрены.

## Сервис и проверка

0.2.0 выравнивает запуск сервиса с существующей учётной записью MGU и группой приложений, использует socket activation, проверяет ответ после запуска и выводит ограниченную диагностику systemd при отказе. Точная причина сбоя прежней версии на автомобиле без журнала не установлена. Не следует считать локальные проверки доказательством устранения именно этого отказа.

На компьютере проверяются исходные сценарии интерфейса Waze и камер, управление по реальным локальным сокетам, дочерний процесс сервиса Node 8, недоступное хранилище, пакетные валидаторы и отправка слоя прозрачности по протоколу renderer. **Systemd, реальный GPS, яркость и расположение на KOMBI/HUD требуют проверки на автомобиле.**

## Сборка

Node.js 18+ на компьютере:

```sh
npm test
node tools/build.js
node tools/test_packages.js
node tools/prepare-github-release.js --output ../output/waze-strelka-release
```

Сборка создаёт исходный пакет интерфейса и native kit сервиса. Закрытый BMW OAP SDK не включён: его берут из собственного firmware donor при установке на MGU. USB-каталог создаётся рядом в `../output/kaluga-cameras-usb`; общие зависимости должны быть доступны на машине/носителе. Сначала публикуются неизменяемые версионные архивы, затем обновляется `catalog.json` и прямой HTTPS-каталог.

## Исправление запуска 0.2.1

В опубликованном интерфейсе 0.2.0 обнаружены повторяющиеся номера компонентов между основным экраном и страницей камер. Это повреждало маршрутизацию действий по ID и могло нарушать создание RHMI. В 0.2.1 номера страницы камер перенесены в отдельный диапазон; сборка проверяет уникальность номеров и согласованность XML/JSON. Нативный сервис не изменялся. Проверка этого дефекта по опубликованному архиву не заменяет журнал запуска конкретной машины.
